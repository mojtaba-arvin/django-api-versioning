# Website instructions

These instructions add website-specific constraints to the repository-root `AGENTS.md`; they do not override its shared Git, security, contribution, or release policies. The canonical website workflow is `.agents/skills/website-engineering/SKILL.md` at the repository root. Do not create a nested skill registry or duplicate client-specific agent instructions here.

Static marketing and documentation site for the `django-api-versioning` Python package. The deployed artifact is static: do not add a runtime backend, database, API route, Server Function, or hosting-provider adapter.

## Architecture

- TanStack Start (React 19) with file routes in `src/routes/`; `src/routeTree.gen.ts` is generated by TanStack Router.
- Vite configures a host-independent static build and prerenders linked routes. Keep `PUBLIC_BASE_PATH` support for both `/` and `/django-api-versioning/`.
- The deployable artifact is `dist/client/`. A server build may be used internally by the build tool to prerender pages, but it must not be part of the deployed artifact.
- Use pnpm 10.12.1 via the `packageManager` field and commit `pnpm-lock.yaml`; do not use npm or generate a `package-lock.json`.
- `src/components/`
  - `HomePage.tsx`: homepage sections.
  - `DocsPage.tsx`: reference tables and sections.
  - `Playground.tsx`: interactive version-matrix editor.
  - `LifecycleDemo.tsx`: simulated HTTP responses per version.
  - `CodeBlock.tsx`: Python/bash highlighter and copy button.
  - `Layout.tsx`: header, footer, logo and GitHub icon.
- `src/lib/matrix.ts`: pure routing-rule model covered by `matrix.test.ts`.
- `src/data/`: site identity, navigation, links and product copy.
- `../docs/reference/index.md` is the canonical Markdown source for `/docs`; `scripts/sync-reference.mjs` copies it into the generated `content/reference/` build input. Do not hardcode Reference content in React or edit the generated copy.
- `../docs/reference/versioning-contract.md` is the detailed written routing contract; verify technical claims against package source and tests.
- Articles: repository-root `docs/articles/*.md` is the only canonical source. `pnpm run sync:articles` copies this local corpus into `content/articles/` and generates `public/rss.xml`. The script must never download from GitHub or another branch. Edit articles only in the root `docs/articles/` directory.
- `src/lib/articles.ts` parses front matter and renders Markdown. `src/lib/article-data.ts` loads the locally generated corpus for route loaders; these are ordinary build-time/local data functions, not server endpoints.
- Routes: `/`, `/docs`, `/articles`, and `/articles/$slug`. Every article page must be prerendered. RSS is a generated static file, not a route handler.
- `scripts/check-dist.mjs` validates the deployable artifact, all canonical article pages, RSS entries, local references, cache-header policy, and absence of server/runtime artifacts. Its tests cover root hosting and `/django-api-versioning/`.
- `public/_headers` is the canonical static-host cache policy: HTML and unhashed public files must revalidate; Vite-fingerprinted `/assets/` files may be cached as immutable. Hosts that ignore `_headers` require equivalent CDN/hosting configuration. Artifact validation proves the policy file is present, not that a deployed host sends the headers.

## Conventions

- Dark theme. Colour and font tokens are defined in `@theme` in `src/styles.css` (`ink`, `paper`, `mute`, `line`, `leaf`, `amber`, `rose`). Use these tokens instead of raw hex values.
- Shared utility classes: `.btn`, `.btn-primary`, `.btn-ghost`, `.card`, `.eyebrow`, `.section-title`, `.inline-code`, `.tok-*`.
- Every factual claim about the package must match the package implementation and canonical README. Do not invent APIs, return values or CLI output.
- The playground is an illustration of the documented rules, not the real implementation. Keep the copy saying so.
- `LifecycleDemo` starts with a fixed date so SSR and hydration render the same output, then switches to the real clock in an effect. Keep browser-only APIs inside effects and handlers.

## Package-backed examples

- Keep the rendered website unchanged when refreshing verification data: do not alter layout, copy, code-block presentation, or Playground interaction merely to make a check pass.
- The endpoint example in `src/data/content.ts` must remain byte-for-byte aligned (apart from trailing newlines) with `integration_test_project/segment_lab/scenarios/website_quick_start.py`. That fixture is executed against the repository package and its route responses are checked.
- The `check_versions` example is compared with output generated by the dedicated `website_check_versions` scenario. Do not hand-edit generated output.
- `scripts/verify_website_examples.py` is run by `.github/workflows/website-data-preflight.yml` after the Segment Lab generator. Package, test, integration, and evidence-harness changes must run this website gate.
- If package behavior changes, inspect the failing executable evidence first. Update a public example only when its behavior is intentionally changing and the user-facing change is separately approved; otherwise preserve the example and correct the implementation or fixture as appropriate.
